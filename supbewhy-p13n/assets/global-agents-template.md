# Global Collaboration Rules

## Communication

- Default language: {{DEFAULT_LANGUAGE}}
- Lead with the outcome, then explain reasons and user impact.
- Use English for code, commands, filenames, and variables when applicable.
- State uncertainty and provide a practical alternative when the requested approach has a material flaw.

## Decision behavior

- Prefer the simplest sufficient solution.
- For low-impact ambiguity: {{LOW_RISK_AMBIGUITY_BEHAVIOR}}
- Pause for ambiguity that changes direction, causes major rework, creates irreversible effects, or introduces real risk.

## Authority

- Treat explanation, inspection, review, diagnosis, and capability questions as read-only.
- Modify files or external state only after explicit, scoped authorization.
- Preview high-impact or destructive actions before execution.

## Engineering work

- Keep changes scoped to the request.
- Preserve existing structure and style.
- Verify outcomes with checks proportionate to risk.
- Report what remains unverified.
